# API 설계서

> 문서 상태: 초안 v0.1 (2026-11-05) · 산출물 4/9
> **Day 1 동결 대상** — 변경은 이 문서 PR로 먼저 합의한다.

## 1. 기본 정보

- **Base URL**: `http://localhost:8080/api` (배포: `http://<EC2>/api`, Nginx 프록시)
- **인증 방식**: JWT — `Authorization: Bearer <accessToken>` / Refresh Token은 HttpOnly 쿠키 `baton_rt`
- **Content-Type**: `application/json` (업로드는 `multipart/form-data`, 채팅 응답은 `text/event-stream`)
- 회원가입 API 없음 (계정은 Flyway 시드)

## 2. 공통 응답 형식

성공
```json
{ "success": true, "data": {}, "message": "" }
```

실패
```json
{ "success": false, "error": { "code": "DOC_NOT_FOUND", "message": "문서를 찾을 수 없습니다." } }
```
- 500 응답에 스택 트레이스·SQL·내부 경로를 포함하지 않는다.

목록(페이징)
```json
{ "success": true, "data": { "content": [], "page": 0, "size": 10, "totalElements": 4, "totalPages": 1 } }
```

## 3. 인증 API

| 메서드 | 경로 | 인증 | 설명 |
|--------|------|------|------|
| POST | `/auth/login` | X | 로그인 |
| POST | `/auth/refresh` | 쿠키 | Access 재발급 + Refresh 교체 |
| POST | `/auth/logout` | O | Refresh 폐기, 쿠키 삭제 |
| GET | `/auth/me` | O | 내 정보 |

### 3.1 로그인 — `POST /auth/login`
요청
```json
{ "email": "sales.staff@baton.local", "password": "********" }
```
응답 200 (+ `Set-Cookie: baton_rt=...; HttpOnly; Secure; SameSite=Strict; Path=/api/auth`)
```json
{ "success": true, "data": {
    "accessToken": "eyJ...", "expiresIn": 1800,
    "member": { "name": "김영업 사원", "department": "SALES", "rank": "STAFF" } } }
```
실패
- 401 `AUTH_INVALID_CREDENTIALS` — `"remainingAttempts": 3` 포함
- 423 `AUTH_LOCKED` — `"lockedUntil": "2026-11-10T14:20:00+09:00"`

### 3.2 토큰 재발급 — `POST /auth/refresh`
- 본문 없음, 쿠키의 Refresh Token 해시를 DB와 대조 → 새 Access + 새 Refresh(기존 폐기)
- 401 `AUTH_REFRESH_INVALID` (만료·폐기·재사용 감지)

### 3.3 내 정보 — `GET /auth/me`
```json
{ "success": true, "data": { "name": "김영업 사원", "department": "SALES", "rank": "STAFF" } }
```
- 내부 `id`, `uuid`는 응답에 포함하지 않는다.

## 4. 문서함 API

| 메서드 | 경로 | 인증 | 설명 |
|--------|------|------|------|
| GET | `/documents` | O | 권한 범위 문서 목록 (검색·페이징) |
| POST | `/documents` | O | 문서 업로드 |
| GET | `/documents/{id}` | O | 문서 상세(메타데이터) |
| DELETE | `/documents/{id}` | O | 문서 삭제 (업로더 본인) |

### 4.1 목록 — `GET /documents?keyword=정산&page=0&size=10&sort=createdAt,desc`
- 권한 밖 문서는 목록·건수(`totalElements`)에 포함하지 않는다.
```json
{ "success": true, "data": { "content": [
  { "id": 3, "title": "거래처 관리 매뉴얼",
    "author": { "name": "김영업", "rank": "STAFF" },
    "createdAt": "2026-11-09T10:12:00+09:00",
    "department": "SALES", "minRank": "STAFF", "status": "READY", "mine": true }
], "page": 0, "size": 10, "totalElements": 4, "totalPages": 1 } }
```
- `sort` 허용 필드: `createdAt`, `title` (그 외 400)

### 4.2 업로드 — `POST /documents` (`multipart/form-data`)
| 필드 | 필수 | 규칙 |
|------|------|------|
| file | O | PDF·DOCX, ≤ 10MB, 확장자 + MIME + 매직넘버 일치 |
| department | O | `ALL` 또는 내 부서 |
| minRank | O | `STAFF` / `LEADER` (사원은 `STAFF`만) |
| title | X | 미입력 시 파일명 사용, 최대 200자 |

응답 201
```json
{ "success": true, "data": { "id": 11, "status": "READY", "chunkCount": 12, "maskedCount": 2 } }
```
실패: 400 `FILE_INVALID_TYPE` / 413 `FILE_TOO_LARGE` / 403 `DOC_FORBIDDEN_SCOPE`(타 부서·권한 초과 지정) / 502 `AI_INGEST_FAILED`

### 4.3 상세 — `GET /documents/{id}`
- 권한이 없거나 없는 문서 → 둘 다 **404 `DOC_NOT_FOUND`** (존재 여부 숨김)

### 4.4 삭제 — `DELETE /documents/{id}`
- 업로더 본인만, 권한 밖 → 404, 열람 가능하지만 본인 아님 → 403 `DOC_NOT_OWNER`
- DB 행 + Chroma 청크 동시 삭제 → 204

## 5. AI 업무 채팅 API

| 메서드 | 경로 | 인증 | 설명 |
|--------|------|------|------|
| GET | `/chat/sessions` | O | 내 대화 목록 |
| POST | `/chat/sessions` | O | 새 대화 |
| GET | `/chat/sessions/{id}/messages` | O | 대화 메시지 이력 |
| POST | `/chat/sessions/{id}/messages` | O | 질문 → SSE 스트리밍 답변 |
| DELETE | `/chat/sessions/{id}` | O | 대화 삭제 |

- 모든 `{id}`는 세션 소유자 검증, 타인 세션 → 404

### 5.1 질문 — `POST /chat/sessions/{id}/messages`
요청 (부서·직급 등 권한 값은 받지 않는다)
```json
{ "question": "정산 마감이 언제야?" }
```
- `question`: 1~1,000자

응답 `text/event-stream`
```
event: token
data: {"text":"매월 25일까지 "}

event: token
data: {"text":"ERP에 입력하고 팀장 승인을 받습니다."}

event: sources
data: [{"docId":3,"title":"거래처 관리 매뉴얼","page":2}]

event: done
data: {"messageId":42}
```
- 권한 범위에 근거 문서가 없을 때: `token` 1건 `"권한 범위의 문서에서 찾을 수 없습니다."` + `sources: []`
- 오류: `event: error` / `data: {"code":"AI_UNAVAILABLE","message":"잠시 후 다시 시도해 주세요."}`
- Frontend는 POST + 헤더가 필요하므로 `EventSource` 대신 `fetch` + `ReadableStream`으로 수신, 답변은 텍스트로 렌더링(`dangerouslySetInnerHTML` 금지)

### 5.2 메시지 이력 — `GET /chat/sessions/{id}/messages`
```json
{ "success": true, "data": [
  { "id": 41, "role": "USER", "content": "정산 마감이 언제야?", "createdAt": "..." },
  { "id": 42, "role": "ASSISTANT", "content": "매월 25일까지 ...", "sources": [{"docId":3,"title":"거래처 관리 매뉴얼","page":2}], "createdAt": "..." }
] }
```

## 6. 내부 API (Backend → AI Module)

> Docker 내부 네트워크 전용, 외부 미공개. 모든 요청에 `X-Internal-Api-Key` 필수(불일치 401).

| 메서드 | 경로 | 설명 |
|--------|------|------|
| GET | `/health` | 헬스체크 (키 불필요, HEALTHCHECK용) |
| POST | `/internal/ingest` | 문서 수집 |
| POST | `/internal/chat` | 권한 필터 RAG 답변 (SSE) |
| DELETE | `/internal/documents/{docId}` | 문서 청크 삭제 |

### 6.1 `POST /internal/ingest` (`multipart/form-data`)
| 필드 | 설명 |
|------|------|
| file | 원본 파일 |
| docId | DB 문서 ID |
| title | 문서명 |
| department | `SALES` / `DEV` / `ALL` |
| minRank | `STAFF` / `LEADER` |

응답 `{ "docId": 11, "chunkCount": 12, "maskedCount": 2 }`

### 6.2 `POST /internal/chat`
```json
{
  "question": "정산 마감이 언제야?",
  "filter": { "departments": ["SALES", "ALL"], "ranks": ["STAFF"] },
  "history": [ { "role": "USER", "content": "..." } ]
}
```
- `filter`는 Backend가 DB의 member 정보로만 생성한다.
- 응답 이벤트 형식은 5.1과 동일 (`token`, `sources`, `done`, `error`)

## 7. HTTP 상태 코드

| 코드 | 설명 | 대표 오류 코드 |
|------|------|----------------|
| 200 | 성공 | |
| 201 | 생성 | |
| 204 | 삭제 성공 | |
| 400 | 잘못된 요청·검증 실패 | `VALIDATION_FAILED`, `FILE_INVALID_TYPE` |
| 401 | 인증 실패·토큰 만료/위조 | `AUTH_INVALID_CREDENTIALS`, `AUTH_TOKEN_INVALID` |
| 403 | 권한 부족 | `DOC_NOT_OWNER`, `DOC_FORBIDDEN_SCOPE` |
| 404 | 없음 또는 권한 밖 리소스 | `DOC_NOT_FOUND`, `SESSION_NOT_FOUND` |
| 413 | 파일 크기 초과 | `FILE_TOO_LARGE` |
| 423 | 계정 잠금 | `AUTH_LOCKED` |
| 500 | 서버 오류 (상세 미노출) | `INTERNAL_ERROR` |
| 502 / 503 | AI 모듈 오류·타임아웃 | `AI_INGEST_FAILED`, `AI_UNAVAILABLE` |

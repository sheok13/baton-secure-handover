# **8. 컨테이너 배포 가이드**
> 문서 상태: 초안 v0.1 (2026-11-06) · 산출물 8/9

## **1. 컨테이너 구성**
바톤(Baton) 프로젝트는 보안과 확장성을 고려하여 총 5개의 컨테이너로 구성됩니다.
  - **Frontend**: React (Vite) + Nginx (웹 서버 및 프록시)
  - **Backend**: Spring Boot 3 + Java 17
  - **AI Module**: FastAPI + Python 3.12 + LangChain
  - **Database**: MariaDB 11.x
  - **Vector DB**: Chroma (AI 문서 임베딩 저장소)

## **2. Docker 설정 (Dockerfile)**
보안(비root 계정 실행)과 최적화(멀티스테이지 빌드, 레이어 캐싱)를 적용한 각 모듈의 Dockerfile 구성입니다. .dockerignore를 통해 환경변수(.env) 및 로컬 패키지가 이미지에 포함되지 않도록 차단

### **2.1 Frontend Dockerfile (frontend/Dockerfile)**
```dockerfile
# 1단계: 빌드 환경 (Node)
FROM node:22-alpine AS build  
WORKDIR /app  
COPY package*.json ./  
RUN npm ci  
COPY . .  
RUN npm run build

# 2단계: 실행 환경 (Nginx)
FROM nginx:alpine
# 비root 권한 부여 및 보안 설정
RUN chown -R nginx:nginx /usr/share/nginx/html && \
    chmod -R 755 /usr/share/nginx/html  
COPY --from=build /app/dist /usr/share/nginx/html  
USER nginx  
EXPOSE 80  
HEALTHCHECK --interval=30s --timeout=5s CMD curl -f http://localhost/ || exit 1
CMD ["nginx", "-g", "daemon off;"]
```

### **2.2 Backend Dockerfile (backend/Dockerfile)**
```dockerfile
# 1단계: 빌드 환경 (Gradle + JDK)
FROM eclipse-temurin:17-jdk AS build
WORKDIR /app
COPY . .
RUN ./gradlew clean build -x test

# 2단계: 실행 환경 (JRE)
FROM eclipse-temurin:17-jre
WORKDIR /app
RUN useradd -m batonapp
COPY --from=build /app/build/libs/*.jar app.jar
RUN chown batonapp:batonapp app.jar
USER batonapp
EXPOSE 8080
HEALTHCHECK --interval=30s --timeout=5s CMD curl -f http://localhost:8080/actuator/health || exit 1
CMD ["java", "-jar", "app.jar"]
```

### **2.3 AI Module Dockerfile (ai-module/Dockerfile)**
```dockerfile
FROM python:3.12-slim
# uv 패키지 매니저 사용
COPY --from=ghcr.io/astral-sh/uv:0.12.23 /uv /uvx /bin/
WORKDIR /app
RUN useradd -m aiapp
COPY pyproject.toml uv.lock ./
RUN uv sync --locked --no-dev
COPY . .
RUN chown -R aiapp:aiapp /app
USER aiapp
EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=5s CMD curl -f http://localhost:8000/health || exit 1
CMD ["uv", "run", "uvicorn", "app.api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

## **3. Docker Compose (infra/docker-compose.yml)**
내부망(baton-net)을 구축하여 **Frontend만 외부로 노출**하고, 나머지 서비스(DB, AI 등)는 외부 접근을 완벽히 차단한 Zero-Trust 네트워크 구조입니다.

```yaml
version: '3.8'

services:
  database:
    image: mariadb:11.2
    container_name: baton-db
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD}
      MYSQL_DATABASE: baton_db
      MYSQL_USER: baton_app
      MYSQL_PASSWORD: ${DB_PASSWORD}
    volumes:
      - db-data:/var/lib/mysql
    # ports 미지정: 외부 통신 차단
    restart: unless-stopped
    networks:
      - baton-net

  ai-module:
    build:
      context: ../ai-module
    container_name: baton-ai
    env_file: ../.env
    # ports 미지정: 백엔드에서만 내부 통신으로 접근
    restart: unless-stopped
    networks:
      - baton-net

  backend:
    build:
      context: ../backend
    container_name: baton-backend
    env_file: ../.env
    depends_on:
      - database
      - ai-module
    restart: unless-stopped
    networks:
      - baton-net

  frontend:
    build:
      context: ../frontend
    container_name: baton-frontend
    ports:
      - "80:80"  # 프론트엔드만 유일하게 외부 개방
    depends_on:
      - backend
    restart: unless-stopped
    networks:
      - baton-net

volumes:
  db-data:

networks:
  baton-net:
    driver: bridge
```

## **4. 환경 변수 및 비밀정보 관리**

### **4.1 환경 변수 관리 원칙**
  - 실제 키가 포함된 `.env` 파일은 `.gitignore`에 등록하여 **절대 Git 이력에 커밋하지 않습니다.**
  - 저장소에는 값들이 모두 비워져 있는 `.env.example` 템플릿만 커밋하여 팀원들과 형식을 공유합니다.

### **4.2 주요 환경 변수 (.env.example 기준)**
```env
# [인증·보안]
JWT_SECRET_KEY=               # 32바이트 이상 문자열
AI_INTERNAL_API_KEY=          # Backend ↔ AI 내부 통신용 인가 헤더 값

# [데이터베이스]
DB_PASSWORD=                  # MariaDB 계정 비밀번호

# [AI 모듈]
LLM_API_KEY=                  # 확정된 LLM 제공자 API Key
AI_BASE_URL=http://ai-module:8000
```
  - **운영(CI/CD) 환경:** EC2 배포 시 필요한 실제 비밀정보 값들은 GitHub Secrets에 등록하여 Actions를 통해 주입합니다.

## **5. 클라우드 배포 (AWS EC2)**
  - **보안 그룹 세팅:** 인바운드 규칙은 웹 서비스용 80 포트(HTTP)와 관리자 접속용 22 포트(SSH, 팀 IP 한정)만 개방합니다.
  - **배포 절차:**
```bash
# EC2 서버 내부 배포 스크립트 예시
cd /home/ubuntu/baton-secure-handover  
git pull origin main
# 사전에 .env 파일은 EC2 내부에 직접 생성
cd infra  
docker compose pull  
docker compose up -d --build
```

## **6. CI/CD (GitHub Actions)**
`main` 브랜치에 코드가 병합될 때마다 자동으로 이미지를 빌드하고 Docker Hub로 푸시하는 파이프라인을 구축합니다.

* **워크플로우 대상:** Frontend, Backend, AI Module
* **사용한 GitHub Secrets:** `DOCKERHUB_USERNAME`, `DOCKERHUB_TOKEN`, 운영용 API 키 세트

## **7. 네트워크 포트 및 보안 통제**
모든 컨테이너는 `baton-net`이라는 내부 브릿지 네트워크로 통신합니다. 웹서버 역할을 하는 Frontend 이외의 어떠한 포트도 호스트(EC2) 밖으로 게시(Publish)하지 않습니다.

| 서비스 | 포트 | 외부 공개 여부 | 통제 사유 및 접근 권한 |
| --- | --- | --- | --- |
| Frontend | 80 | O (공개) | 사용자 브라우저 접속 처리 및 백엔드로 /api 프록시 전달 |
| Backend | 8080 | X (비공개) | Nginx 프록시(Frontend)를 통한 접속만 허용 |
| AI Module | 8000 | X (비공개) | Backend 컨테이너에서만 X-Internal-Api-Key를 동반하여 접근 가능 |
| Database | 3306 | X (비공개) | Backend 컨테이너에서만 접근 허용 (DB 직접 탈취 방지) |
| Vector DB | - | X (비공개) | AI Module 내부에서만 임베딩 데이터 입출력용으로 사용 |

## 6. 취약점 조치 상세 (대표 3건 이상 필수)

> 가장 의미 있는 취약점 3건 이상에 대해 아래 형식으로 작성합니다.

### 6.1 AI 모듈 내부 API 무단 호출 (AI 모듈 · D)

- **관련 항목**: OWASP API2:2023 Broken Authentication / 점검서 A-1
- **재현 방법**:
  1. AI 모듈 실행 후 키 헤더 없이 `curl.exe -X POST http://localhost:8000/internal/chat -H "Content-Type: application/json" -d "{...}"` 호출
  2. 인증이 없으면 Backend의 로그인·권한 검사를 건너뛰고 임의의 filter로 질문·업로드 가능
- **영향**: 조작한 권한 필터로 타 부서 문서 열람, 임의 문서 업로드·삭제
- **조치 전 코드**: `/internal` 라우터에 인증 없음 (설계 초기 상태)
- **조치 후 코드** (`app/api/deps.py`):
  ```python
  def verify_internal_key(x_internal_api_key: str | None = Header(default=None)) -> None:
      expected = get_settings().ai_internal_api_key.get_secret_value().encode("utf-8")
      given = (x_internal_api_key or "").encode("utf-8")
      # bytes끼리 비교: 헤더에 비ASCII 문자가 섞여도 TypeError(500) 없이 401로 끝난다
      if not given or not hmac.compare_digest(given, expected):
          raise ApiError(status.HTTP_401_UNAUTHORIZED, "INTERNAL_AUTH_FAILED", "내부 인증에 실패했습니다.")
  ```
- **재확인 결과**: 키 없음·틀린 키·비ASCII 키 → 401, 올바른 키 → 통과 (`test_health.py` 3건 통과, curl 401 응답 캡처 첨부)

### 6.2 문서 속 개인정보가 VectorDB·LLM으로 유출 (AI 모듈 · D)

- **관련 항목**: OWASP LLM02:2025 Sensitive Information Disclosure / 점검서 A-3
- **재현 방법**:
  1. 가짜 연락처·계좌번호가 들어간 DOCX 업로드
  2. 원문 그대로 Chroma에 저장 → 검색 결과로 외부 LLM에 전달 → 답변에 노출 가능
- **영향**: 개인정보가 벡터 저장소에 영구 저장, 외부 LLM 전송, 다른 직원 답변에 노출
- **조치 전 코드** (`app/api/routes_ingest.py`):
  ```python
  docs = load_document(data, file.filename or "")
  chunks = split_documents(docs)
  ```
- **조치 후 코드**:
  ```python
  docs = load_document(data, file.filename or "")

  # 개인정보 마스킹 — 분할 전에 적용 (명세서 5.1 ②)
  masked_count = 0
  for d in docs:
      d.page_content, n = mask(d.page_content)
      masked_count += n

  chunks = split_documents(docs)
  ```
- **재확인 결과**: 예시 문서 3·4·9·10번 `maskedCount` 2, 저장소로 가는 글에 원래 번호 없음 (`test_ingest_masks_before_saving`, `test_pii_masker.py` 12건 통과)

### 6.3 권한 밖 문서 내용이 답변에 노출 (AI 모듈 · D)

- **관련 항목**: OWASP A01 Broken Access Control, LLM08:2025 Vector and Embedding Weaknesses / 점검서 A-3
- **재현 방법**:
  1. 영업 사원 필터(`departments=[SALES,ALL]`, `ranks=[STAFF]`)로 개발팀·팀장 전용 문서 내용 질문
  2. filter 없이 또는 빈 filter로 `/internal/chat` 호출
- **영향**: 부서·직급이 다른 문서 내용이 답변·출처에 노출
- **조치 전 코드**: filter 검증 없음, 답변 불가 시에도 출처 첨부
  ```python
  sources = format_sources(docs)
  ```
- **조치 후 코드**:
  ```python
  # schemas.py — filter 필수, 빈 목록 거부
  class AccessFilter(BaseModel):
      departments: list[Department] = Field(min_length=1)
      ranks: list[Rank] = Field(min_length=1)

  # errors.py — filter 오류는 400 FILTER_INVALID (fail-closed)
  if any("filter" in map(str, err.get("loc", ())) for err in exc.errors()):
      return JSONResponse(status_code=400, content=_body("FILTER_INVALID", "권한 필터가 올바르지 않습니다."))

  # routes_chat.py — "찾을 수 없습니다" 답변이면 출처 비움
  sources = [] if answer.strip() == NO_ANSWER_MESSAGE else format_sources(docs)
  ```
- **재확인 결과**: 4개 계정 × 권한 밖 질문 5건 = 20건 노출 0건, 대조군 4/4 정상 (`permission_result.md` 첨부), `test_rejects_missing_filter`·`test_rejects_empty_filter` 통과
